审查日期：2026-09-08。源码基准：`47a5863`。本次只新增审查报告，没有修改算法、配置、数据划分或运行状态。

结论：任务有研究意义，但当前是位姿补偿的数据与部署原型，尚未完成真正的 Mamba、可信动态监督和闭环精度验证。“FAST-LIVO2 + Mamba + 位姿残差”本身不足以证明论文创新；值得验证的方向是几何退化期间可泛化、因果、具备可信拒绝机制的时序误差补偿。

## 2. 当前系统到底实现了什么

实际主链：

```text
LiDAR/IMU -> 时间同步与去畸变 -> IMU 传播 -> LIO ESIKF
 -> 记录补偿前 basic18 历史 -> ONNX/dummy -> 限幅/拒绝
 -> 可选写回 _state -> 导出 CSV -> 重建当前点云及其方差 -> 写入体素地图
 -> 下一帧 IMU/LIO；启用图像时另有 VIO 更新
```

正面结果：补偿插入点明确；默认 observe-only；ONNX 输入输出有维度/类型检查和异常回退；当前点云世界坐标在地图更新前重算；正式 M3DGR 管线有 bag 级划分、train-only 归一化、右 SE(3) 重建校验，并保留超出运行时限幅的有效大误差标签。这些是有价值的工程基础。

尚未完成：两个 `train_mamba_pose_*` 脚本实现的网络均是 FlattenMLP。没有真正的 selective state-space/Mamba 训练器、正式 GT 训练器及其完整在线闭环实验。`static_zero` 证明零输出接口，`pseudo_smooth_reference` 学的是轨迹平滑参考，均不能证明定位误差减少。

## 3. 按优先级列出的发现

### F1 / P1：监督标签与运行时修正不兼容

位置：`scripts/build_m3dgr_mocap_dataset.py:240`；`src/pose_compensator.cpp:1142`。

标签为 `xi = Log(T_est^-1 T_ref) = [theta,rho]`。C++ 则用 ZYX 欧拉角构造右乘旋转，直接将后三维加到世界系位置。正确的右 SE(3) 写回为：

```text
R_new = R_est Exp_SO3(theta)
p_new = p_est + R_est J_l(theta) rho
```

其中 `J_l` 是 SO(3) 左雅可比。已有状态 `operator+=` 也是局部旋转/世界平移混合误差定义，不能直接把右 SE(3) 六维向量原封不动塞进去。

数值反例：`R_est=Rz(90°), rho=[0.1,0,0], theta=0`，期望世界位移 `[0,0.1,0]`，现实现给 `[0.1,0,0]`，两者相差 0.141421 m。小限幅不能修正方向错误。

处置：GT 模型维持 observe-only。迁移时增加机器可读的标签语义、坐标系、输出顺序、单位、特征 schema、归一化哈希及模型版本校验；旧模型与新模型不能仅凭输出长度为 6 互换。

### F2 / P1：formal 数据组装的可信性检查未形成完整证据链

位置：`scripts/build_m3dgr_mocap_dataset.py:127,188`；`tests/test_m3dgr_pipeline.py:299`。

报告入口主要检查 `run_id/status`。测试本身用只有这两个字段的 JSON 就成功生成 formal 数据，说明它没有强制验证 `all_trust_gates_passed`、物理 frame 确认证据、输入及对齐输出内容哈希。CSV 中 offset/frame/extrinsic 的一致性主要是文件内/运行间一致性，不是对报告及 manifest 的全面核对。bag SHA256 校验虽在 prepare 工具中实现，后续组装并未把 CSV 绑定回那份已验证 bag；冻结 covariance profile 也没有被完整强制执行。

影响：误配同名报告、CSV 修改、不同基线导出混用等操作错误仍可能被接受为 formal 数据。这里的风险是科研产物追溯，不是恶意文件攻击。

处置：沿 bag -> conversion/rewrite -> baseline config/commit -> raw CSV -> alignment -> dataset 保存并验证哈希及关键配置，添加错误配对、哈希不符、profile 未冻结、trust gate 未通过的拒绝测试。不能只把合成 fixture 扩写为更多标签字符串而不验证其来源。

### F3 / P1：手眼标定缺少可观测性、收敛与残差门槛

位置：`scripts/estimate_m3dgr_handeye.py:102,205`。

使用相对旋转幅值和运动对数量筛选，跨 run 变换差小于 2 cm/1°就标为 consistent；没有用雅可比秩/奇异值检查自由度是否可观测，求解器 `success` 和绝对残差也没有进入一致性判定。

复现：构造仅绕 z 转动且在 xy 平面平移的 25 组运动，真实外参平移 `[0.05,-0.03,0.30]`。调用现有 `solve_handeye` 返回 success=True，z 约 -0.000791 m，平移残差中位数约 1.62e-9 m。竖直杆臂不可观测，低残差不是正确标定的证据。多条同样退化的轨迹可能给出相似错误解。

处置：检查加权残差雅可比的秩、条件数及参数不确定度；要求求解成功和残差阈值；校准数据提供多轴激励或独立测量约束。物理刚体定义确认与数值外参可观测性必须分别通过。不要用待改进的 LIO 在退化轨迹上标定外参，再把同源误差当独立 GT。

### F4 / P1：核心 LIO 存在未初始化的收敛标志

位置：`src/voxel_map.cpp:400,511`。

`bool flg_EKF_inited, flg_EKF_converged, EKF_stop_flg = 0;` 只初始化最后一个变量。若第一次迭代不满足收敛条件，后面会读取未初始化的 `flg_EKF_converged`，属于未定义行为，可能影响 rematch/退出及协方差更新时机。

这是当前核心代码的问题，不是已证明由 Mamba 改动引入的问题。正式基线导出前应修复并验证不收敛/后续收敛路径；本次审查未修改该受保护文件。

### F5 / P1：LiDAR 点时间到去畸变的契约存在漏洞

位置：`src/preprocess.cpp:175`；`src/LIVMapper.cpp:1230`；`src/IMU_Processing.cpp:289,516`。

Livox 非特征分支对相邻时间差 >=1 ms 的点改写为前一点加 0.004166667 ms；这隐含特定扫描速率假设。LIO 用末点时间作为扫描结束时间，IMU 去畸变又按点数组倒序跨 IMU 时间区间扫描，但该分支没有按时间排序。保留原始 CDR/offset 不等于估计器实际按正确时间使用每个点。

本地 Corridor02 首条 MID360 消息：19,968 点，原始 offset 有 139 处逆序。按当前配置过滤后保留 16,334 点；本次首帧的时间改写误差为 0（不能声称该首帧被改写）。逆序说明输入并非天然严格有序；其对轨迹的量化影响仍需回放或针对真实 IMU 时间边界检查。

处置：使用真实 offset、保留异常诊断；扫描末时刻取正确最大值；去畸变采用排序或按每点时间查找对应 IMU 区间。覆盖乱序、大时间间隔、被过滤末点等测试，避免网络学习预处理错误。

### F6 / P1（闭环前）：离线目标与闭环系统不是同一分布

位置：`src/LIVMapper.cpp:573,581,722,786`；`src/pose_compensator.cpp:1165`。

网络在未补偿基线轨迹上学习累计位姿残差；一旦写回，下一轮状态传播、匹配、地图和历史输入都会改变。连续预测原基线的累计修正，可能重复补偿，而不是预测当前残差。当前代码改变 R/p，保留完整协方差和速度/bias，也未提供统计一致性的更新模型。

只重建当前帧点云不能自动修复旧地图和视觉参考点。旧地图与新位置约束相互拉扯可能掩盖或反转离线收益。这里不是断言一定发散，而是当前没有证据证明稳定。

处置：先验证独立输出分支 `T_out=T_base Exp(xi)` 的可预测性；随后用闭环 rollout 重新生成当前状态的残差，比较直接写回与具备不确定度/拒绝机制的融合。若视作虚拟观测，必须讨论网络输入与 ESIKF 共享数据导致的相关性，不能把它无条件当独立传感器再更新一次。

### F7 / P2：现有 baseline 验证不能作为泛化证据

位置：`scripts/train_mamba_pose_pseudo_label.py:270,574`；`scripts/train_mamba_pose_static_zero.py:393`。

两个训练器使用 FlattenMLP 和窗口 random_split。相邻 T=10、stride=1 窗口共享 9 帧，随机划分导致强重叠。旧流程先计算整条序列归一化，再在训练器拆分，验证信息也参与特征统计。对称平滑标签可以作为离线 teacher，但它不是 GT；未来数据如果进入 X 插值，则又是因果输入不一致。

正式 M3DGR 组装已经有 bag-level split/train-only norm，这是正确方向；不能又送入旧训练器重新 random_split。为正式 GT 写专用训练/评估入口，严格读取固定 train/val/test 文件。只在训练集内打乱 minibatch 是允许的。

### F8 / P2：basic18 的信息量和坐标泛化不足

位置：`src/pose_compensator.cpp:1047`。

输入是绝对位置、世界姿态四元数、世界速度、bias、有效特征数量和平均绝对残差；不含 dt、原始 IMU、方向性退化信息、创新向量或状态协方差。时间戳虽存入历史，却没有进入网络。

不同误差方向可以有相同残差均值；仅看轨迹不能唯一识别真实位置偏差。网络可能学习运动平滑或场景坐标，而不是定位误差。绝对坐标、四元数双覆盖及 train/runtime 四元数符号处理差异需要实验检查。

处置：先做相对位姿/局部速度/dt 输入；四元数统一符号连续性或换连续旋转表示。增加少量物理诊断量：预测到更新的位姿创新、残差分位数、有效比例、归一化信息矩阵谱/方向、IMU 统计。信息矩阵混合 rad/m 单位，不能直接拿未尺度化条件数当可靠退化指标。

### F9 / P2：在线时序有效性没有匹配离线分段规则

位置：`src/pose_compensator.cpp:878`；`scripts/build_m3dgr_mocap_dataset.py:146`。

离线拒绝非单调时间和超过 0.2 s 的跨窗间隔；在线 pushState 只追加历史，没有对应时间跳变清空、输入有限性检查和 readiness 重置。丢帧/回放重启时，模型可能吃到训练集从未出现的窗口。部分测试配置 min_ready_frames=3 而 history_len=10，会提前触发静态 T=10 模型的形状失败；正式配置使用 10，不能把测试配置直接带入正式实验。

若未来采用 streaming Mamba，隐藏状态也必须在 bag/segment 边界清空；若每次重新输入完整滑窗，则不能对外宣称已实现跨窗持久记忆。

### F10 / P2：日志与实验时间语义需要修正

位置：`src/LIVMapper.cpp:573,581,659,733,1619`。

- 网络历史记录补偿前状态，但 CSV 在写回后导出；闭环时 X 与导出 pose 不再对应同一个节点。正式 dummy/observe-only 导出暂时不受影响。
- `applyPoseCompensationIfNeeded()` 恒返回 false；当前调用者丢弃返回值，所以目前未阻止重建，但未来若用它触发重建会出错。
- `applied=true` 只由开关决定，拒绝/失败回退时也可能如此，不能据此统计真实修正率。
- ROS odometry/path 使用 `now()`，CSV 使用测量时刻；launch 发 `--clock` 未显式给节点设置 use_sim_time。即使设 use_sim_time，处理完成时刻也不等于状态测量时刻。评估优先使用明确测量时间戳，后续统一发布语义。
- launch 对 bag_path 先 abspath 再检查空串，使空路径变成当前目录，校验失效；节点/播放并行启动也缺少订阅 ready 保障，可能损失开头数据。

### F11 / P2：时间对齐和安全机制尚未覆盖可信运行

位置：`scripts/mamba_pose_se3.py:291`；`scripts/align_m3dgr_mocap_gt.py:388`；`src/pose_compensator.cpp:1102`；`CMakeLists.txt:29`。

时间搜索记录相关性分数，却没有把峰值可靠性、边界命中、分段稳定性纳入 trust gate。速度相关使用不同物理点，转动杆臂会改变线速度，因此未知外参时也不能盲信平移速度相关。跨 bag 时差一致不是所有采集系统的必然事实，阈值应有同步依据。

安全限幅是逐轴限幅，不是旋转/平移向量范数上限；每帧 0.2 m 也不是整段轨迹稳定性保证。非有限值拒绝可被配置关闭，ARM Release 又使用 `-ffast-math`，未来在 ARM 部署时必须专门验证有限性检查没有被编译假设消除。不能用 x86 工程安全测试替代目标设备认证。

## 4. 建议明确的研究目标

更可检验的表述：**利用因果时序中的运动和几何诊断信息，预测几何里程计在退化期间的局部位姿误差，并以可拒绝、可校准的方式融合，提高真实闭环精度和恢复能力。**

不要预设网络能恢复任意不可观测的绝对平移/yaw。缺少新测量信息时，模型提供的是数据驱动先验；需要实验证明其适用范围和失败条件。

保留现有右 SE(3) 绝对残差作为首个 observe-only 目标，同时比较局部运动增量误差：

```text
D_est(t) = inv(T_est(t-1)) T_est(t)
D_gt(t)  = inv(T_gt(t-1))  T_gt(t)
y_inc(t) = Log(inv(D_est(t)) D_gt(t))
```

增量目标降低起点/世界坐标依赖，但必须明确定义如何组合回轨迹，不能只换 y、不改推理与积分语义。绝对残差与增量残差哪个更有效，应由固定验证集决定。

推荐最小模型：因果输入编码 -> 少量 Mamba block -> 最后一时刻 6D residual head；首先不要引入无必要的多分支架构。输出不确定度可以作为后续对照，但增加一个 uncertainty head 本身不是创新。

| 阶段 | 应完成工作 | 通过标准 |

| A：可信基线 | 修复收敛标志、确认点时间；完成冻结 Varying-illu02 Pilot 获取/校验/转换/导出 | 测量时刻及轨迹连续；零模型与关闭补偿可重复对照；没有隐式时间重写或丢帧混入 |

| C：可学习性 | 六个训练 bag 与固定验证 bag；zero、线性、MLP、GRU/TCN、Mamba | 独立 bag 的位置/旋转误差与离线修正 ATE/RPE 优于零修正；不是只有训练 loss 降低 |
| D：因果部署 | raw-input ONNX；统一特征和 SE(3)；窗口、reset、异常输入测试 | Python 与 C++ 相同 raw 窗口的特征/输出/修正姿态一致；无未来输入；报告目标设备延迟 |
| E：闭环 | 与独立输出分支区分；按当前 rollout 重标残差；拒绝/融合实验 | ATE/RPE 改善且失败率不升，地图质量不退化，长期累积偏置与恢复行为可解释 |
| F：论文证据 | 第二环境/数据集、跨场景测试、多种子、消融与相关方法比较 | 主要贡献对新场景成立，Mamba 相对便宜模型有精度或效率收益 |

当前最近的工程里程碑仍是 A/B：完整真实 Pilot 和可信标签，不是加深网络或启用 apply=true。Pilot 属于 test，只能用于预先限定的管线检查，不能凭其 ATE 挑模型、限幅、窗口或 covariance profile。若已经反复据其精度调参，需要如实披露并另留 untouched test；本次不更改冻结划分。

M3DGR 当前关闭 camera，Dark/Varying-illu/Occlusion 的视觉挑战不必然构成 LIO 退化，Wheel-float 的轮滑也不直接作用于未使用轮速的 LIO。先测量几何退化及实际误差峰值。LIO 阶段适合排除因素，但最终若宣称改进完整 FAST-LIVO2，需要加入 LIVO 模式对照和 VIO 更新之后的最终轨迹评价。

建议预先登记以下实验，不按测试结果选择有利序列：

- 基础模型：原始 baseline、dummy/zero、线性或 MLP、GRU/TCN、等规模 Mamba；必要时小 Transformer。
- 时序：T=1/10/30/100、打乱历史顺序、去掉历史、滑窗与持久状态。T=10 很短，长序列优势不能靠复杂度公式代替实测。
- 信息：basic18 与局部特征；移除绝对位置；有/无 dt、IMU、退化诊断；旋转世界坐标并验证等变/不变关系。
- 融合：独立输出、直接写回、带拒绝的融合；有/无不确定度；报告拒绝率、限幅率、拒绝样本的误差。
- 指标：每 bag 平移/旋转 ATE，多个时间尺度 RPE，失败率，退化段及恢复段误差，地图厚度/重影，延迟 p50/p95/p99、内存、参数量，多种子波动。
- ATE 必须明确首段对齐与标准全轨迹 SE(3) 对齐的区别；同协议比较。Mocap 有尺度，不应任意用 Sim(3) 吸收尺度误差。置信区间按 bag/独立运行统计，不能把重叠窗口当独立重复实验。

如果 C 阶段 basic18 连 MLP/GRU 都不能稳定超过 zero，应先检查信息量、GT 和目标定义；如果 Mamba 与 GRU 持平，应调整贡献表述，而不是靠增大模型掩盖这一结果。

## 6. 论文意义与创新判断（检索至 2026-09-08）

以下为本次检索到的原始论文/出版页面；不是穷尽性系统综述，也不能据此保证不存在更接近工作。

| 相关工作 | 与本项目重叠的部分 |

| [Learning a Bias Correction for Lidar-only Motion Estimation, 2018](https://arxiv.org/abs/1801.04678) | 已用几何特征和 GP 学习传统 LiDAR 估计器的位姿偏差并修正 |

因此，“首次 Mamba 用于里程计”“首次时序残差纠偏”“Mamba + uncertainty + Kalman”均不宜作为未经限定的创新主张。StreamVLO 不等于本项目：它是学习式视觉-LiDAR odometry，而这里可以研究既有几何 ESIKF 的补偿；但仅替换宿主为 FAST-LIVO2 不足以形成强贡献。

可争取的贡献是：针对几何退化方向的时序误差建模、与估计器相关性/状态重置相容的补偿策略，以及严格证明离线收益如何转化为闭环收益和跨场景泛化。这些目前都是待验证假设，不能在摘要中提前写成已实现或理论保证。

判断：工程/应用价值成立；当前代码和证据尚不足以支撑强创新论文。若只接入 Mamba 并在单条同场景轨迹降一点 ATE，论文说服力弱。若完成上述数据、因果和闭环链条，并相对简单时序模型与近邻方法证明可重复的优势，则有形成完整论文的潜力；不对录用或投稿档次作保证。
